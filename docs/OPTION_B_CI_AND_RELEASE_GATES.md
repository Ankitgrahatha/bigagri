# Option B delivery pipeline and remaining blockers

## Pipeline created

`.github/workflows/rewardloop-quality-gate.yml` runs in GitHub Actions and is independent of Vercel deployments. It checks JavaScript syntax, runs API/replay contract tests, and runs the existing read-only boundary smoke script.

This is an incremental CI gate. It is not a database transaction test and does not certify production readiness.

## Repository baseline gap

The live Supabase project reports 13 applied migrations, but the repository currently contains only four SQL migration files, and the `supabase/` tree does not contain `supabase/config.toml`. Therefore a clean local Supabase instance cannot yet be recreated reliably from this repository. A local database workflow must not be represented as passing until the complete migration baseline is safely captured, scrubbed of sensitive data, committed, and validated from an empty local database.

## Required next work

1. Restore the missing historical schema migrations from an authoritative schema-only export / migration history. Do not dump production user data into Git.
2. Add a reviewed `supabase/config.toml` generated by the pinned Supabase CLI.
3. Run `supabase start`, `supabase db reset`, and `supabase test db` on an isolated CI runner.
4. Add pgTAP tests for grants, role/membership checks, cross-tenant access denial, claim replay, and redemption stock/balance invariants.
5. Add deterministic integration tests for concurrent/replayed claims and redemptions using synthetic local fixtures.
6. Add a protected deployment workflow for reviewed Supabase migrations / Edge Functions only after staging verification. Production secrets must be configured in GitHub Actions secrets and must never be printed.
7. Keep Vercel out of the build/test path while its Hobby deployment quota is blocked. Once the release passes, deploy the verified main commit to Vercel and smoke-test the exact production deployment.

## Production safety

No production migration was applied by this CI setup. No production functions were disabled. No claims, balances, redemptions, or stock were modified.
